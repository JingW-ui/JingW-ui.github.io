Onward — 离线优先的项目看板与记录工具

面向团队的 Windows 桌面应用：离线优先的个人工作管理 + 多端云同步的项目看板。 桌面端 Tauri 2 + React + TypeScript + SQLite，云端 FastAPI 同步服务 + Web 门户。 个人数据只留本机，团队看板实时同步。本页为公开版文档，部署凭据与内部信息不在公开范围。

角色 独立设计与开发 状态 已上线（v1.1.7） 技术栈 Tauri 2 · React · TS · SQLite · FastAPI 文档 2026-09

项目定位

Onward 把「个人工作」与「团队协作」放在同一个离线优先的应用里： 个人工作——计划完成、今日待办、会议日程、快速记录（备忘录 / 工作任务报告 / 流程图）， 全部数据仅存本机；团队协作——项目看板（任务、里程碑、导入历史）支持桌面端与网页版多端云同步， 由自建的 FastAPI 云同步服务与 Web 门户承载。

两个入口：Web 看板（onward.heartshinemedical.com/board）· 桌面端（Windows 安装包，门户提供版本化下载）。

云同步架构（v1.1.7）

三端组成，各司其职：

端职责
桌面端 Tauri 2 应用内置同步引擎——成员输入 token 后自动后台同步看板，无需手动触发
云端服务 FastAPI：看板 GET 拉取 / PUT 推送（乐观锁）、SSE 实时广播、版本清单与安装包下载（token 或 60 秒一次性票据）、token 管理端点、审计日志
Web 门户 React SPA：成员登录查看 / 编辑看板、下载安装包；管理员创建 / 重置 / 停用 / 启用成员 token（支持邮件通知）
  • 实时性：有人推送看板后，服务端通过 SSE 版本广播通知所有客户端立即拉取；断线错过的事件由最长 5 分钟轮询兜底，多端最终一致。
  • 合并策略：按 updatedAt 记录级 last-write-wins——不丢数据，冲突以最新修改为准。
  • 容量边界：看板 20000 个任务上限，单任务 200 条待执行事项。
  • token 生命周期：停用 / 删除即刻返回 401，桌面端与网页版同时断开；重新启用后原 token 无需任何配置即恢复。
  • 隐私边界：个人数据（待办 / 计划 / 会议 / 记录）永不上云，仅项目看板参与同步。

数据与可靠性

  • 存储：SQLite 事务 + FULL 同步落盘；数据库路径稳定，升级保留全部历史数据。
  • 本地版本备份：启动后首次修改先自动备份再保存，此后至少每 30 分钟保留一份；默认保留 20 份（可选 5–50），支持一键备份与完整版本恢复，恢复前强制保护当前数据。
  • 最近删除：待办、计划与整场会议均可恢复，保留原日期、图文、完成状态与计划关联；保留数量 20–500 可配。
  • 保存保护：草稿在切换栏目 / 关闭窗口时提示保存；保存失败保留未保存状态并提示重试；原始数据读取失败时不覆盖数据库。
  • 快速记录容量：记录 5000 条上限；流程图 200 节点 / 400 连线，全套内容遵守 64MB 状态上限。

工程与质量

  • 测试矩阵：单元测试（数据规则 / 备份校验 / 排序 / 保存故障恢复）、Playwright 浏览器交互测试、NSIS 安装器隔离卸载测试、真实 EXE 的 WebView2 + SQLite 编辑流程测试、草稿离开与窗口关闭专项、自动填充与重启数据保留、会议待办双向同步、记录图片剪贴板快捷键、备份与恢复专项，以及 Rust 后端 cargo test。
  • 交付：版本化安装包 + SHA256 校验文件 + 专属卸载程序；GitHub Release 与云端下载页双通道分发，历史版本可回退。
  • 桌面工程：WebView2 原生标题栏拖动、系统托盘常驻、禁用通用自动填充保护工作数据；八款应用图标由统一 SVG 几何生成前端 PNG 与多尺寸 Windows ICO，发布不可变版本化路径避免缓存冲突。
