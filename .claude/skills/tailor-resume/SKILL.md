# 定向简历生成技能

## 这个技能做什么

用户给出一个岗位 JD，你产出**一份针对该岗位定制的单页 A4 HTML 简历**，放在 `resume/resume_qz/` 目录下（**全部为秋招简历**），文件名形如 `resume_<公司或岗位>.html`。核心价值是**适配性**：不是把所有经历平铺，而是按 JD 的职责与要求重新编排、取舍、排序、措辞，让 HR 一眼看出"这个人就是为这个岗位来的"。

> **目录约定（2026-09 起）**：`resume/resume_qz/` 放**秋招**简历，`resume/resume_sx/` 放**暑期实习**简历（历史遗留，不再新增）。本技能只产出 `resume_qz/` 下的秋招简历。

## 信息来源（务必遵守）

用户是**王京**，他的全部背景以这两个文件为**唯一权威来源**，每次生成前都要读取（信息可能更新，不要凭记忆）：

- `cv/index.html` — 精简版简历，含个人信息、教育、科研、实习、项目、获奖、证书、技能、爱好
- `resume/index.html` — 详细版简历，项目描述更完整

生成前先 Read 这两个文件，把可用的"原材料"梳理出来。为加速 JD 适配，`references/profile-inventory.md` 里有一份**项目清单索引**（每个项目的名称 / 技术栈 / 担任角色 / 成果 / 链接），用它快速挑选该 JD 该强调哪些项目。若索引与 cv/resume 实际内容冲突，**以 cv/resume 为准**并提示用户更新索引。

## JD 适配方法论（这是技能的灵魂）

定向简历 ≠ 把通用简历换个标题。按下面的步骤做适配：

1. **拆解 JD**：把 JD 的"职位职责"和"条件要求"各拆成几条关键能力点（如"Web 跨平台开发""Vue""AI 提效工具""大模型落地""团队协作"）。

2. **能力点 ↔ 原材料映射（三档判定）**：对每个能力点，从项目清单里挑出**最对口**的 1-3 个项目/经历去支撑。同时把 JD 里的关键词按下列三档判定，**只有前两档的关键词才允许出现在简历里**（借鉴 Resume-Matcher 的 injectable / non-injectable 机制）：

   | 档位 | 定义 | 处理 |
   |---|---|---|
   | 命中 | JD 能力点 + 简历原材都有 | 前置、`primary` 高亮、用 JD 原词改写 |
   | 可注入 | 简历原材有、但初稿漏写 | 把原材里的对应事实补写进来，自然织入措辞 |
   | 不可注入 | JD 有、简历原材没有 | **省略，绝不出现该 JD 原词**——硬凑反而暴露短板 |

   判定依据永远以 `cv/index.html` / `resume/index.html` 的实际内容为准，不要凭印象判断"可注入"。

3. **重排顺序**：与 JD 最相关的板块/项目**前置**。例如 JD 是"跨平台 Web 开发"就把"跨平台/Web 项目经验"放前面；JD 是"AI 提效"就把"AI 提效与智能化工具开发"放前面。JD 强调的能力点对应的技能标签用 `primary` 样式高亮——`primary` 是**灰底 + 黑字加粗**（`color:#1a1a1a; font-weight:700`），与普通标签同底色，仅靠更黑更粗的字重区分，避免深色填充块过于刺眼。

4. **改写措辞**：用 JD 的**关键词原词**改写项目描述。JD 说"跨平台架构与组件体系"，项目描述里就用"架构设计 / 组件复用 / 多端一致性"这类词；JD 说"大模型能力落地开发流程"，就明确点出"将 LLM/Agent 能力落地到 XX 流程"。这是让 ATS（简历筛选系统）和 HR 命中关键词的关键。**改写只限第 2 步三档判定里的"命中"与"可注入"两档**——"不可注入"档的关键词禁止出现在简历任何位置。改写时同时规避 `references/ai-phrase-blacklist.md` 里的 AI 腔词汇。

5. **新增"个人优势"段**：放在最顶部、教育背景之前。用 1 段（最多 2 段）把"我为什么适配这个岗位"讲清楚，直接呼应 JD 的核心要求，并放量化成果（Star 数、用户数、GPA 排名、与主张直接对应的奖项）。全段 ≤5 句（约 280 字），超出先删形容词再删句子。

6. **取舍**：单页 A4 容量有限。与 JD 无关的板块（如投前端岗时的"体育奖项""健身博主"）果断删掉，把空间让给相关内容。保留获奖/科研里**与岗位相关或能体现学习能力**的部分即可。

## 输出规范

- **单个 HTML 文件**，无外部依赖（不引 FontAwesome 等 CDN；图标/emoji 一律不用）。头像走站内相对路径 `/imgs/life_and_others/myavtar.png`。模板中的 FILL 注释是填充位，按注释填好后删除注释本身；`.hl-red` 样式已内置模板，无需再自行添加。
- **A4 单页**：用 `.page` 容器（`width: 210mm; min-height: 297mm`），含 `@media print` 打印适配，Ctrl+P 可另存为干净 A4 PDF。完整 CSS 见 `assets/template.html`——**直接复用该文件的 CSS**，不要重新发明样式。模板里的 `@page { size: A4; margin: 5mm 10mm }`、FILL 注释与打印适配块**必须保留**，原因见下。

  > **打印所见即所得（2026-09 定稿）**：模板的 `@media print` **不做字号压缩**，打印沿用屏幕字号、只去掉阴影；`@page { size: A4; margin: 5mm 10mm }` 保留（叠加 `.page` 自身 padding 提供留白）。**导出想去掉日期/标题水印：在打印对话框里取消勾选"页眉和页脚"**（不要用 `@page margin 0` 方案，2026-09-21 已回退）。因为**项目经验 ≤2 个**后内容天然在单页内，不需要缩小字体。同时布局断点必须写成 `@media screen and (max-width: 820px)`——A4 打印视口宽约 794px **小于** 820px，若不限 `screen`，打印/另存 PDF 时会误触移动端布局，header 的头像与信息会变成上下排列。**这两条都不要改回去。**
- **风格对齐 cv/index.html**：居中 header（头像 + 信息块）、左侧 4px 黑色色条 `.section-title`、`.subsection` 间浅灰分隔线、`.label-link`（灰）/ `.github-label-link`（绿）两类标签链接。
- **教育背景必须包含学院与研究方向**：每条教育经历的 `.subsection-title` 必须写"学校 · 学院 · 专业 · 学历"（学院不可省，如"生命科学与技术学院""信息工程学院"，从 cv/resume 或 profile-inventory 取真实学院名）。`.date` 行之后追加一行 `<div class="tech-line"><em>研究方向：</em>单一研究方向（只写一条）</div>`。方向关键词从 JD 职责中提取（如 JD 提"信号处理""医学影像""智能化应用"，就把对应方向写进去），让教育背景直接呼应岗位需求。**研究方向只写一条**：取"真实科研域 ∩ JD 能力域"的交集，优先用 JD 原词改写；本科同样只写一条。禁止堆砌方向凑排比（2026-09 定稿：宁少勿假）。
- **专业技能用流式文本，不用按钮/标签样式**：去掉 `.skill` `.skill.primary` 的灰底边框按钮感，改用 `.skill-line` + `.skill-cat` + `.skill-hl` 的纯文本流式排版。格式为两行：`<div class="skill-line"><span class="skill-cat">分类名：</span><span class="skill-hl">核心技能1</span> · 技能2 · <span class="skill-hl">核心技能3</span> · ...</div>`。`.skill-cat` 分类标题加粗黑色，`.skill-hl` 核心技能加粗深色突出，其余技能保持灰色常规字重，用 ` · ` 中点分隔。紧凑、省空间、更像传统专业简历。**最多 2 行**（仅页面紧张才压成 1 行），每行 ≤6 项：第 1 行 = 与 JD 最相关的复合能力域（分类名按 JD 命名），第 2 行 = 编程语言与基础。
- **单页高度硬限制 + 专业技能是第一裁剪项（2026-09-26 定稿，经纬恒润简历实测沉淀）**：生成后必须实测 `.page` 的 `scrollHeight`，硬上限 **1123px**（297mm @96dpi），目标留 ≥50px 余量（打印视口更窄、换行更多，实测高度是乐观值）。**超限时的第一裁剪手段 = 整块删除专业技能板块**，其次才压获奖行数/间距——技能信息与"个人优势"+ 各条目 `tech-line` 高度重复，删它信息损失最小。删除前做关键词保全：只在该板块出现的关键词（如 Function Calling、Prompt 工程）**挪进最相关实习/项目条目的 `tech-line` 行**，再用 keyword_check 复验不掉覆盖率。母简历 `resume/index.html` 的「技能」板块**不参与此规则**——它无单页约束，是通用简历的 HR 快扫区，不做裁剪。
  版面实测方法（无头 Edge，`--print-to-pdf` 在部分环境会报 "Multiple targets" 不可靠，用 dump-dom 方案）：把简历 HTML 复制到临时文件，在 `</body>` 前注入 `<script>addEventListener("load",function(){setTimeout(function(){document.title="PAGE_H="+document.querySelector(".page").scrollHeight;},400);});</script>`，用 `--headless=new --virtual-time-budget=5000 --dump-dom` 渲染后从 `<title>` 里读数值。
- **AI 编程工具统一表述为 Claude Code（2026-09 定稿）**：简历中不出现 Cursor——技能行、项目描述、个人优势一律如此；需要泛指时写「AI 编程工具」。DeepSeek Harness 只用于评测轨迹可视化语境（参考其源码实现过程可视化），不当编码工具表述。
- **红字突出重点内容**（`.hl-red`，`color:#fd0000; font-weight:600`）：把最抓眼的量化成果与硬资质标红，让 HR 扫读时第一时间命中。必标红的对象包括：GitHub Star 数（如 `200+ Star`、`70+ Star`）、用户规模（`150+ 用户社群`）、核心荣誉资质（`四川省优秀毕业生 · 推免生`、`发明专利 1 项，软件著作权 5 项`）等。标红要克制——每块 1-3 处即可，全红等于不红。`.hl-red` 样式定义需随 CSS 一起写入生成的 html（已内置在 template.html，无需再自行添加）。
- **获奖/奖学金重复次数用 ×N 标注**：同一奖项多次获得时写"国家励志奖学金 ×2""电子科技大学优秀研究生 ×2""学业奖学金一等奖 ×2"，不要拆成多行也不要省略次数——×N 本身就是量化亮点。生成时逐项核对次数，以母简历 / profile-inventory / 用户现场确认为准（2026-09 确认：电子科技大学优秀研究生 ×2、学业奖学金一等奖 ×2）。
- **奖项与主张的对应关系（2026-09 定稿）**：括号里的奖项必须能**直接证明**括号前的主张——项目类奖项只挂对应项目成果，学科竞赛只挂对应技能域；竞赛奖不是"功底扎实"的通配证据（如国赛一等奖 = 生物医学工程创新设计竞赛，≠ C/C++ / 数据结构功底）。个人优势中不出现无对应关系的奖项括号；与主张无直接对应的硬资质一律只在获奖荣誉板块展示。
- **数字溯源（真实性硬规则）**：简历中出现的**所有量化数字**（Star 数、用户数、GPA、排名、获奖次数、专利/软著数、日期等）必须能在 `cv/index.html` / `resume/index.html` 原文中找到，**禁止新增或改动母简历里没有的数字**——尤其 `.hl-red` 标红内容被 HR 核查概率最高。两个例外：① 版本号（Python 3.10、Vue 3 等）；② 母简历原文已有的年份。确需新数字（如新获奖）只能来自用户提供的新信息，并在第 7 步汇报时注明来源。
- **定制简历项目最多 2 个、实习经历最多 2 条（2026-09 定稿硬性要求）**：项目经验区最多放 **2 个**最对口的 subsection，实习经历最多保留 **2 条**——宁缺毋滥，最相关的放前面；其余项目/实习的能力通过"个人优势"、专业技能体现。用详情版母简历（resume/index.html）的条目池挑选时尤其要克制。
- **实习经历与教育背景严格按 resume/index.html（不得改写时间）**：单位名、岗位名、日期、技术栈、条目文本全部取自 `resume/index.html`，禁止自己编造或缩写时间段。特别注意：**网易互娱实习的时间写 2026.07 - 2026.09**；心曜医疗 2026.03 - 2026.06；国网宁夏 2023.10 - 2023.12。教育背景写"电子信息大类-生物医学工程"、导师与实验室（陈华富 · 神经信息教育部重点实验室 / 周颖玥 · ACM项目组 && BMELab）也按 resume/index.html。header 信息行用"男 · 24岁 · 重庆"（不写政治面貌）。
- 为塞进单页 A4，正文 12px、标题 14px，间距收紧；内容超出/不足一页时调整间距或增删板块，但**优先保证单页**。
- header 的个人信息行**不要写政治面貌**（如"中共党员"）。格式参考：`男 · 24岁 · 硕士`，下接电话/邮箱/微信/GitHub/主页。
- header 顶部加一行"求职意向：XX 岗位 / XX 方向（公司名）"，用蓝色 `.target` 样式。**通用版（一份多投）**时去掉公司名与地域，只写"求职意向：XX 岗位 / XX 方向"。
- 保留项目里的真实链接（GitHub、论文、用户群、证书页），href 直接复用 cv/resume 里的原 URL。
- **每个项目都要写「项目职责」+「项目成果」两条目**：项目经验区每个 `.subsection` 的 `<ul>` 末尾加 `<li><strong>项目职责：</strong>...</li>`（"角色 + 职责范围"句式，如实反映独立负责人 / 主导 / 主要负责人）和 `<li><strong>项目成果：</strong>...</li>`（量化产出：Star 数、用户数、论文、获奖、上线规模等，能标红的用 `.hl-red`）。两者都是硬性要求，不可省略——投递系统会校验"职责及成果"，缺一会被判不完整。

## 工作流程

1. Read `cv/index.html` 和 `resume/index.html`，Read `references/profile-inventory.md`。
2. 与用户确认 JD（如果用户已在消息里给出就直接用；若 JD 模糊，问一句要"公司+岗位名"用于命名文件和求职意向行）。**同时必须拿到该岗位的「投递链接」**——它是卡片墙的必填字段，见第 5 步。
3. 按"JD 适配方法论"拆解、映射、重排、改写。
4. Read `assets/template.html`，基于它的 CSS 结构填充定制内容，Write 到 `resume/resume_qz/resume_<公司或岗位>.html`。
5. **关键词覆盖自检（必做）**：从第 1 步拆解的 JD 关键词中取核心词（通常 10-20 个），用 `references/keyword_check.py` 对生成的 HTML 做整词匹配检查：

   ```bash
   python references/keyword_check.py resume/resume_qz/resume_xxx.html keywords.txt
   ```

   `keywords.txt` 每行一个关键词，同义词可用 `|` 分隔（如 `LLM|大模型`），建议生成时顺手写在临时目录再删。脚本输出命中/缺失清单与覆盖率。**缺失词若属于"可注入"档 → 回到第 4 步补写后重跑自检；属于"不可注入"档 → 属正常缺失，如实汇报即可**。禁止宣称"100% 匹配"——把缺口一起报给用户。

6. **版面自检（必做）**：按「单页高度硬限制」条目的 dump-dom 实测法测 `.page` 的 `scrollHeight`，**≤1123px 且留 ≥50px 余量**才算过；超限先整块删专业技能板块（关键词挪进 tech-line），仍超再压获奖行数或板块间距。改完必须复测。
7. **更新简历墙数据源**：把新简历追加进 `resume/tailored.json`（这是卡片墙 `resume/tailored.html` 的数据源，页面会读取它动态渲染卡片，所以这一步**必做**，否则新简历不会出现在墙上）。追加规范见下方"简历墙数据源规范"，**其中秋招卡片必须带 `applyLink` 与 `jd`**。
8. 生成后简述：你按 JD 强调了哪几点、前置了哪些板块、删掉了哪些无关内容，**附上自检的关键词覆盖率与缺失词清单**（标注哪些是"不可注入"的正常缺失）与**版面实测高度**，让用户快速核对适配方向是否正确。并提示可用浏览器 Ctrl+P 预览 A4。

## 投递链接从哪来（重要）

**不要凭记忆编造投递链接**，必须取自项目里的真实岗位数据：

- 岗位池：`tracker/tracker.pool.json`（含 `id` / `title` / `company` / `city` / `score`）
- 完整 JD + 投递链接：`data/offerio_by_company_state.json`，按公司名索引，每条含 `applyLink` / `responsibilities` / `requirements` / `detail` / `location`

先用**公司名 + 岗位名**在 `data/offerio_by_company_state.json` 里定位该岗位，取其 `applyLink`。北森系（`*.zhiye.com`）链接形如 `https://<tenant>.zhiye.com/campus/detail?jobAdId=<uuid>`。

拿到链接后**务必实际打开验证能访问**（`playwright-cli goto` 后看页面是否渲染出岗位标题与 JD），确认无误再写入 JSON。若数据源里查不到该岗位的链接，**停下来问用户要**，不要猜一个填进去。

> 注意：数据源里的 `location` 可能与线上页面不一致（岗位开放城市会变）。写卡片时**以线上页面实际显示的城市为准**。

## 简历墙数据源规范

`resume/tailored.json` 是一个 JSON 数组，每个元素对应一份定制简历的一张卡片。生成新简历后，向数组**末尾追加**一个对象。

**秋招卡片（`resume_qz/`，本技能产出的唯一类型）字段**：

```json
{
  "index": "33",
  "company": "公司 · 批次/地点",
  "role": "岗位名称",
  "direction": "方向短语（如 AI Agent / RAG / 算法）",
  "tags": ["标签1", "标签2", "标签3", "标签4"],
  "date": "2026.09",
  "url": "/resume/resume_qz/resume_xxx.html",
  "match": "high",
  "applyLink": "https://xxx.zhiye.com/campus/detail?jobAdId=<uuid>",
  "jobId": "J13398",
  "jobTitle": "测试开发工程师",
  "location": "合肥 / 武汉 / 西安 / 苏州",
  "jd": {
    "duty": ["职责1", "职责2", "职责3", "职责4"],
    "req": ["要求1", "要求2", "要求3", "要求4"]
  }

```

要点：

- `index`：两位序号，接续现有最大值 +1。**总数不用手动改**——`tailored.html` 的标题计数与筛选按钮徽标都是从 JSON 实时算出来的。
- `url`：站内相对路径，指向第 4 步生成的 html，**必须在 `/resume/resume_qz/` 下**（卡片墙靠这段路径判定"秋招"并渲染 `applyLink` / `jd`；`/resume/resume_sx/` 的卡片不渲染这两项）。
- `match`：匹配度。填 `"high"` 显示"高匹配"绿徽章；普通岗位留空字符串 `""`。判断依据：JD 核心要求与你背景高度对口（如 AI Agent 岗 + 你有 NEURA）才算 high，不要滥用。
- `tags`：3–4 个，用 JD 关键词，与简历里高亮的技能呼应。
- **`applyLink`（秋招必填）**：官方投递页直链，取自 `data/offerio_by_company_state.json`，并实际打开验证过。卡片上渲染成可点击的「投递链接」按钮，新标签页打开。
- **`jobId` / `jobTitle` / `location`**：岗位编号、岗位名、工作地点。`jobId` 显示在投递链接旁（如"岗位编号 J13398"），`location` 显示在 JD 面板首行。`jobTitle` 用于对照线上岗位。
- **`jd`（秋招必填）**：`duty`（岗位职责）与 `req`（任职要求）各 **2–4 条短句**。卡片上是折叠面板，点「岗位 JD」展开，所以**要压缩改写**成适合卡片宽度的短句，不要照搬带「1、2、3、」序号的长原文。职责要覆盖 JD 的核心工作内容，要求要覆盖学历/语言/经验等硬门槛。
- 追加时**保持 JSON 合法**（逗号、引号、无尾逗号）。追加后无需改 `tailored.html`——它 fetch 这个 JSON 动态渲染，筛选、计数、JD 面板全自动。
- 若是**重新生成/更新**一份已有简历（同公司同岗），不要新增卡片，而是更新 JSON 里对应那条记录（按 url 或 company 匹配）。

### 卡片墙交互约定（改 `tailored.html` 时须知）

- 卡片是 `<div class="card">` + **覆盖式链接** `<a class="card-hit">`，**不是** `<a class="card">`。原因：卡片内要放「投递链接」和「岗位 JD」按钮，而 `<a>` 里套 `<a>` 是非法 HTML，浏览器会提前闭合外层 `<a>`，把这两个元素挤出卡片。**不要改回 `<a>` 包裹整个卡片。**
- `.apply-row` / `.jd-panel` 需保持 `position: relative; z-index: 2`，才能盖在覆盖链接之上被点到。
- 整卡点击（打开简历）与卡内按钮点击（开投递页 / 展开 JD）由 `grid` 上的事件委托区分，不要给卡片加 `onclick`。


## 何时问、何时直接做

- JD 清晰、公司/岗位名明确 → 直接生成，不要反复确认。
- JD 只给职责没给公司名 → 生成前问一句公司名（用于文件名和求职意向行），其余直接做。
- 用户后续要求调整（换风格、加内容、改页数）→ 直接改，不必重走全流程。
